## 2026-07-24 独立复核：CAP-005、CAP-008

### CAP-005｜本地库搜索与结果播放｜blocked

- 已核对实现：`internal/server/store.go` 通过 `works.search_text` 检索，包含标题、描述、UP 主、标签、音乐及拼音/首字母；`FeedWithOptions` 仍组合 UP 主、收藏夹和目录范围。`web/src/pages/FeedPage.tsx` 将搜索状态传给集中式 `api.feed`，播放器可继续切换结果。
- 已核对自动化覆盖：`internal/server/store_test.go` 覆盖元数据检索、拼音/首字母、UP 主范围隔离和历史索引回填；`web/src/components/FeedViewer.test.tsx` 覆盖搜索提交；`web/e2e/localbilibili.spec.ts` 的定向搜索用例在 Chromium 中通过，但 API 由 route mock 提供，并非本地真实样例服务。
- 缺口：`scripts/real-user-e2e.mjs` 只对真实服务发起 Feed 搜索 API 请求，`runBrowserFlow` 未在浏览器填写搜索框并验证返回结果/播放。因此没有满足本项目“真实浏览器访问”的 CAP-005 搜索与结果播放证据。
- 复现/验证：`rtk go test ./...`（154 项通过）；`rtk npm test --prefix web`（99 项通过）；`rtk npm run build --prefix web`（通过）；在 `web/` 执行 `rtk proxy npx playwright test e2e/localbilibili.spec.ts --grep 'immersive feed shows overlays and sends search query' --workers=1`（1 项通过，mock）；`rtk proxy npm run test:e2e`（16 项中多项失败，不能作为回归通过证据）。
- 修复建议：在 `scripts/real-user-e2e.mjs` 或真实服务 Playwright 用例中，导入样例后填写“搜索本地作品”，断言请求携带 `search`、仅显示命中项，并实际播放/浏览该命中项；完成后重跑完整 Playwright。

### CAP-008｜近期内容入口｜blocked

- 已核对实现：`internal/server/store.go` 定义 `three_days`、`week`、`works` 三种 `recent_mode`；前两者按 `published_at` 截止时间筛选，“最近作品”按 1 天、3 天、7 天、1 个月逐步扩大窗口。`internal/server/app.go` 对非法 `recent_mode` 返回 400；`web/src/App.tsx` 提供“最近三天 / 最近一周 / 最近作品”导航和路由，`FeedPage` 透传 `recentMode` 给 `api.feed`。
- 已核对自动化覆盖：`internal/server/store_test.go` 覆盖 3 天、一周、无发布时间排除和“最近作品”窗口扩大；`docs/test-cases.md` 已写明 API 预期。
- 缺口：没有 `/api/feed?recent_mode=...` 的 HTTP 契约测试；没有 `FeedPage`/导航三入口的前端测试；没有三条入口的真实浏览器验收。现有 `scripts/real-user-e2e.mjs` 未访问这些路由，`web/e2e/localbilibili.spec.ts` 也没有近期入口用例。完整 Playwright 回归本次多项失败，无法补作通过证据。
- 复现/验证：同 CAP-005 的 Go、Vitest、构建命令均通过；在 `web/` 执行 `rtk proxy npm run test:e2e` 可复现当前浏览器回归失败（例如设置页 fixture 未出现 `/sample/bilibili`、登录页预期未出现）。
- 修复建议：增加 HTTP 测试（3 个合法值、非法值 400、边界发布时间和空日期）；增加前端导航/请求参数测试；在真实样例服务中访问三条近期路由，断言数据边界、图文/视频可打开且桌面和移动端无横向溢出，再通过全量 Playwright 后解除 blocked。
