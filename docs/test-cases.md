# Test Cases

本文件在功能实现前定义测试 case，作为本项目开发门禁。

## LocalBilibili V1 先行门禁

本节定义 LocalBilibili 落地前必须先覆盖的测试 case。下方历史 LocalDouyin 用例在迁移过程中继续作为页面、扫描、更新、播放器和诊断能力的参考，但涉及抖音字段、抖音 Cookie、`aweme_id`、`douyin_*` 的断言必须迁移为 B站语义后才能作为 LocalBilibili 验收依据。

| 名称 | 前置条件 | 操作步骤 | 期望结果 | 风险点 | 层级 |
| --- | --- | --- | --- | --- | --- |
| B站 schema 迁移 | 空 SQLite 数据库 | 启动迁移 | 创建 `bilibili_mid`、`bilibili_space_url`、`bvid`、`aid`、`cid`、`work_type` 等 B站字段；公共 schema 不暴露 `douyin_*` 或 `aweme_id` | 新项目沿用抖音公共契约 | 单元/集成 |
| B站作品类型约束 | 构造 `video_long`、`video_short`、`image_text` 和未知类型输入 | 写入或扫描作品 | 只接受三种 V1 类型，未知类型跳过并记录原因 | 直播、番剧、课程、音频等非目标类型进入本地库 | 单元 |
| 规范元数据扫描 | UP主目录含 `metadata.localbilibili.json`、视频、图片和封面 | 调用扫描器 | 优先读取规范元数据，正确导入 UP主、作品、媒体、封面、发布时间和标签 | 文件名解析脆弱导致误入库 | 单元/集成 |
| 长视频导入 | 样例作品目录含 `work_type=video_long` 和 `media_001.mp4` | 扫描并查询 Feed | 作品入库，媒体类型为 `video`，Feed 可播放 | 长视频不可播放或未入库 | 单元/集成/E2E |
| 短视频导入 | 样例作品目录含 `work_type=video_short` 和 `media_001.mp4` | 扫描并查询 Feed | 作品入库，播放器按视频作品处理 | 短视频被误判为不支持类型 | 单元/集成/E2E |
| 图文导入 | 样例作品目录含 `work_type=image_text` 和多张 `image_*.jpg` | 扫描并打开 Feed | 作品入库，Feed 可左右切换图文媒体 | 图文动态无法保存或浏览 | 单元/集成/E2E |
| 不支持类型跳过 | 样例目录含直播、番剧、课程、纯音频或互动视频元数据 | 扫描或更新 | 任务继续执行，跳过数量和原因可见，不保存媒体 | 单个非目标作品拖垮整次任务 | 单元/联调 |
| yt-dlp 就绪检查 | `LOCALBILIBILI_YTDLP` 未配置或指向不可执行文件 | 管理员触发更新 | API 返回明确错误，不新增 pending 下载任务，不泄露环境路径之外敏感信息 | 下载器损坏时队列被污染或错误不可诊断 | 单元/联调 |
| Bilibili Cookie 管理 | 管理员保存 Bilibili Cookie | 打开更新管理和日志 | 保存状态可见，明文只在授权界面展示，日志和脱敏源数据不包含 Cookie | Cookie 泄露 | 单元/联调 |
| UP主主页导入 | 输入 `https://space.bilibili.com/{mid}` | 批量导入预览并提交 | 解析为 `bilibili_mid` 和 `bilibili_space_url`，创建或复用 UP主 | 无法从 0 添加 B站 UP主 | 单元/联调 |
| 下载结果存储布局 | fake Bilibili 下载器返回长视频、短视频、图文和不支持类型 | 执行立即更新 | 生成 `<safe_name>__mid_<mid>/<YYYY-MM-DD>_<safe_title>_<id>/` 目录、规范 metadata、脱敏 source、媒体文件和封面 | 下载输出无法被扫描器稳定识别 | 单元/集成 |
| yt-dlp 视频下载规范输出 | fake `yt-dlp` 返回空间页列表和视频元数据 | 调用 `BilibiliDownloader.UpdateCreator` | 长视频、短视频分别生成作品目录、`metadata.localbilibili.json`、`source.ytdlp.json`、`media_001.mp4` 和封面；扫描器可直接入库 | 下载器输出与扫描器契约脱节 | 单元/集成 |
| B站 opus 图文下载规范输出 | fake B站 opus HTML 返回图文标题、作者、发布时间和多张 `bfs/new_dyn` 图片 | 调用 `BilibiliDownloader.UpdateCreator` 输入 opus URL | 生成 `work_type=image_text`、`dynamic_id`、多张 `image_*.jpg`、`cover.jpg`、`source.bilibili.json`；扫描器可直接入库 | 图文只能手工拼样例，更新链路无法保存图文 | 单元/集成 |
| 下载后自动扫描 | fake 下载器写入符合存储契约的新作品 | 立即更新 UP主 | 新作品自动入库，新增数量只统计保存的三种类型 | 下载完成后页面不可见或跳过类型计数错误 | 集成 |
| Feed 页面 B站化 | 已登录且数据库有三种 V1 作品 | 打开 Feed、切换作品和媒体 | UI 使用 B站/UP主/作品文案，无抖音字段或 `aweme_id` 暴露 | 复制页面残留抖音文案和字段 | 前端/E2E |
| UP主页 B站化 | 已有 UP主头像、签名、作品 | 打开 UP主列表和详情 | 展示 UP主信息、作品数、最近更新、收藏入口和 B站主页身份 | 作者模型残留B站语义 | 前端/E2E |
| 图文移动端浏览 | 移动端 viewport 打开图文作品 | 左右切换图片、上下切换作品 | 图片不溢出，控件不裁切，触摸行为不误触发多次切换 | 图文在手机端不可用 | E2E |
| 视频播放回归 | 桌面和移动端打开长短视频 | 播放、暂停、拖动进度、音量、画中画、上下切换 | 播放器行为与 LocalBilibili 等价，无控制台严重错误 | 页面 1:1 能力回退 | E2E |
| 样例公开小样本 | 使用公开小样本配置 | 下载每个 UP主最多 3 个 V1 作品 | `samples/bilibili/` 下生成可重复扫描的小样本，至少覆盖视频和图文；样例媒体不进入 Git | 后续测试缺少真实样例 | 集成/手工 |
| 真实样例全流程验收 | 使用 `samples/bilibili/` 公开小样本和干净 SQLite | 启动单体 Go 服务，登录、保存目录、扫描、请求 Feed、打开媒体 Range、进入关注/收藏/更新管理页面，并跑桌面和移动端视口检查 | Feed 返回 `video_long`、`video_short`、`image_text` 三类作品；媒体返回 200/206；UP主名来自 metadata；页面无严重控制台错误，移动端无横向溢出 | 单元和组件测试通过但真实用户流程断裂 | E2E/真实 |
| 真实用户完整验收 runner | 设置 `BILIBILI_COOKIE_FROM_USER`，或无 Cookie 时使用样例兜底 | 运行 `rtk node scripts/real-user-e2e.mjs`；详见 `docs/real-user-e2e.md` | 覆盖真实 UP主新增、重复导入、立即更新、再次更新、收藏夹、多用户隔离、定时队列、Feed 播放、移动端布局、诊断日志与 Cookie 脱敏 | 真实用户路径只靠手工点检，或 Cookie 泄露到仓库/日志/报告 | E2E/真实 |

## 单元测试

| 名称 | 前置条件 | 操作步骤 | 期望结果 | 风险点 | 层级 |
| --- | --- | --- | --- | --- | --- |
| 目录路径校验 | 存在临时目录、文件路径、不存在路径 | 调用目录校验函数 | 仅存在且可读的目录通过 | 非法路径、文件伪装目录 | 单元 |
| 目录浏览过滤 | 临时目录含子目录、普通文件、隐藏文件 | 调用目录浏览函数 | 只返回可读子目录，过滤隐藏噪声 | 浏览器暴露无效项 | 单元 |
| 保存目录去重 | SQLite 空库 | 连续保存同一路径 | 只保留一条目录记录 | 重复配置导致重复扫描 | 单元 |
| 删除目录不删文件 | 已保存目录和真实文件 | 删除目录配置 | 数据库索引移除，真实文件仍存在 | 误删用户本地文件 | 单元 |
| 文件名解析 | 多种 `日期_标题_id` 文件名 | 调用作品解析函数 | 正确提取作品 ID、标题、日期、媒体类型 | 文件名含下划线或中文 | 单元 |
| JSON 元数据提取 | `_data.json` 含 aweme/author/music 字段 | 调用元数据解析 | 提取作者、描述、发布时间、音乐、标签 | JSON 字段缺失 | 单元 |
| 扫描队列串行 | 两个扫描任务 | 连续入队 | 同一时间只运行一个任务 | IO 卡顿、并发写库 | 单元 |
| 单UP主成功即入库 | 样例目录含多个UP主 | 扫描首个UP主 | 首个UP主完成后即可查询到作品 | 扫描完成前不可见 | 单元 |
| Feed 搜索标题描述 | 已入库多条作品 | 按关键词查询 Feed | 仅返回标题或描述命中的作品 | 搜索结果污染随机 Feed | 单元 |
| Feed 搜索UP主标签音乐 | 已入库UP主、标签、音乐字段 | 按UP主名、标签、音乐关键词查询 | 返回对应作品 | 元数据字段无法检索 | 单元 |
| UP主内搜索限定范围 | 两个UP主有相似关键词 | 同时传 `creator_id` 和 `search` | 只返回指定UP主内命中作品 | 跨UP主搜索串数据 | 单元 |

| 立即更新串行去重 | 同一UP主多次点击立即更新 | 调用立即更新入队 | 只进入唯一立即队列并串行执行 | 重复下载、并发写库 | 单元 |
| 缺少身份更新失败 | UP主无线上主页信息 | 加入立即更新队列 | 任务失败并记录明确错误，不阻塞后续UP主 | 队列卡死、错误不可诊断 | 单元 |
| 定时队列 cron 触发 | 定时队列含UP主且 cron 到期 | 调用调度 tick | 队列UP主加入立即队列并记录 run 摘要 | 定时更新不执行 | 单元 |
| Cookie 保存校验 | 管理员输入 Cookie | 保存并校验 Cookie | 保存状态更新，不在日志暴露明文 | Cookie 泄露或不可用 | 单元 |
| 任意作品 JSON 补齐 sec_uid | 已有UP主缺少线上身份，作品目录任意 `.json` 含 `author.sec_uid` | 重新扫描该UP主目录 | creators 补齐 `bilibili_sec_uid` 和 `https://www.bilibili.com/user/{sec_uid}` | 已扫描历史数据无法参与更新 | 单元/集成 |
