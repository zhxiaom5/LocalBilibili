# Changelog

## 0.1.69 - 2026-07-04

- Feed 顶部作品日期在 `published_at` 为空时回退到作品入库时间，仍无法取得时显示“日期未知”，避免真实下载数据日期列消失。

## 0.1.68 - 2026-07-04

- Feed 播放器顶部信息改为 `@UP主 · 作品日期 · 作品标题 · 原链接`，原链接会在新窗口打开 B站原作品。
- Web 侧补齐 favicon、apple touch icon 和 manifest，并复用 fnOS 应用图标作为 LocalBilibili 浏览器识别图标。
- 前端主色从抖音红迁移到 B站蓝/粉暗色体系，主按钮、选中态、进度条和 focus 状态使用 B站蓝，收藏状态使用 B站粉。

## 0.1.67 - 2026-07-04

- UP主头像图片使用 `referrerPolicy="no-referrer"` 加载，避免 B站头像因局域网 Referer 防盗链返回 403 后退回默认图标。

## 0.1.66 - 2026-07-04

- 已有作品的数字/mid 占位 UP主也允许被真实昵称提升，修复历史导入后关注页仍显示 ID 的问题。

## 0.1.65 - 2026-07-04

- UP主资料解析优先使用 B站空间 card 接口，导入和更新时回填真实昵称、头像和签名，不再把 mid 当展示名。
- 下载生成的 `metadata.localbilibili.json` 写入 `creator.avatar_url`，扫描后关注页和 Feed 可展示头像。
- 同一线上身份的数字占位 UP主可被真实资料复用并改名，避免重复关注卡片。

## 0.1.64 - 2026-07-04

- 兼容 `yt-dlp --dump-single-json` 输出前后混入诊断文本的情况，避免 NAS 运行时提示行导致 UP主资料解析失败。

## 0.1.63 - 2026-07-04

- fnOS 包内置 Linux x86_64 `yt-dlp`，启动时显式设置 `LOCALBILIBILI_YTDLP`，避免线上环境缺少 `yt-dlp` 导致 UP主解析和更新失败。
- fnOS 启动 PATH 增加 app 目录和字幕运行时目录，使 `yt-dlp` 可复用包内 `ffmpeg`。

## 0.1.62 - 2026-07-04

- 修复批量新增关注无法识别 `https://space.bilibili.com/<mid>` 标准 B站空间链接的问题。
- B站身份提取兼容 `space.bilibili.com/<mid>`，避免预览、提交和更新链路使用不同解析规则。

## 0.1.61 - 2026-07-04

- 将 fnOS 安装/配置向导默认端口调整为 `8090`，并让浏览器安装脚本自动填写 `wizard_app_port`。
- 浏览器安装脚本兼容 fnOS 的协议许可页和安装设置页，便于复用已有登录态完成安装/升级。

## 0.1.60 - 2026-07-04

- 修正 0.1.59 生命周期回调在 fnOS 解包路径下定位 `cmd/main` 的方式，确保安装/升级回调能正确启动 LocalBilibili 服务。

## 0.1.59 - 2026-07-04
